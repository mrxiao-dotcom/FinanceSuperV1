# 商业蓝图生成机制文档

## 概述

商业蓝图的生成是一个「**预设框架 + LLM智能生成**」的混合过程。系统提供结构化的诊断流程和输出模板，LLM负责填充具体内容并生成战略洞察。

---

## 一、系统预设（Fixed Elements）

这些是由程序员预先编写的、**不可改变**的部分。

### 1.1 五阶段诊断流程

```
Stage1: 探索独占资源 (ExploringExclusiveResources)
Stage2: 挖掘隐性痛点 (ProbingHiddenPainPoints)
Stage3: 确认履约边界 (ConfirmingDeliveryBoundaries)
Stage4: 构建护城河 (BuildingMoat)
Stage5: 生成商业蓝图 (GeneratingBlueprint)
```

### 1.2 五层逼问模板

预设的追问框架，包括触发条件：

| 层次 | 名称 | 触发条件 | 预设问题 |
|------|------|----------|----------|
| 第一层 | 价值显影术 | 用户使用"提升效率""节省成本"等模糊词 | "帮客户省下的具体时间是多少小时？" |
| 第二层 | 损失放大术 | 用户说不出"不买的后果" | "客户现在不买，30天损失多少？" |
| 第三层 | 决策链定位 | 价值点过于宽泛 | "谁最关心这个问题？" |
| 第四层 | 信任证据夯实 | 拿不出可验证凭证 | "有什么证据让陌生人相信？" |
| 第五层 | 成交场景预演 | 缺少首次接触锚点 | "客户在什么场景下想起您？" |

### 1.3 进度计算规则

预设的百分比分配：

| 维度 | 权重 |
|------|------|
| 独占资源明确 | 20% |
| 目标客户画像清晰 | 15% |
| 隐性痛点充分挖掘 | 20% |
| 竞品盲区定位 | 15% |
| 信任证据链完整 | 15% |
| 交付模式确定 | 15% |

### 1.4 Stage5 输出结构模板

预设的蓝图必须包含的章节：

```
## 一、核心定位
- 一句话超级签名（格式固定："我是谁，我用什么方法，帮谁解决什么问题"）
- 目标客户画像

## 二、价值锚定
- 显性价值（具体数字）
- 隐性痛点（30天内代价）
- 情感溢价

## 三、信任构建SOP
- 成功案例（2-3个）
- 资质背书
- 社交证明

## 四、成交路径
- 首次接触锚点
- 决策链
- 承诺钩子

## 五、交付模式
- 高客单陪伴式
- 轻量级自动化
```

## 二、LLM生成内容（AI-Generated）

以下部分由大语言模型**根据用户输入动态生成**。

### 2.1 具体追问内容

**预设**：使用哪个层次的逼问模板
**LLM生成**：具体的问题措辞和追问逻辑

例如：
- 预设触发条件：用户说了"提升效率"
- LLM生成：`"您提到能帮客户提升效率，具体能省多少时间？比如原来需要3天的工作，现在多久能完成？"`

### 2.2 进度百分比计算

**预设**：进度维度和权重
**LLM生成**：根据对话内容评估每个维度是否"已完成"

LLM需要输出的格式：
```
【商业诊断进度：XX%】
- 独占资源明确 ✓
- 目标客户画像清晰 ✓
- ...
```

### 2.3 商业蓝图完整内容

**预设**：必须包含的章节和格式
**LLM生成**：每个章节的具体内容

| 章节 | LLM生成内容示例 |
|------|----------------|
| 一句话签名 | "我是一个用「抖音矩阵打法」帮实体店在30天内实现线上营收占比超过50%的操盘手" |
| 显性价值 | "帮客户平均每月多赚3-5万，省下每周8小时运营时间" |
| 隐性痛点 | "不学的代价：每月损失潜在客户50-80人，三个月后被竞争对手拉开差距" |
| 情感溢价 | "选择我们的客户看重的是：已经验证过的方法论，而不是试错" |
| 成交路径 | "客户在小红书看到案例文章后，在直播间下单，首次咨询承诺给出具体执行方案" |

### 2.4 竞品分析洞察

**预设**：JSON结构模板
```json
{
    "competitor_blind_spots": [...],
    "our_exclusive_advantages": [...]
}
```
**LLM生成**：具体的盲区和优势分析

## 三、程序后处理（Post-Processing）

在LLM生成内容后，程序会对结果进行解析和结构化。

### 3.1 蓝图Markdown解析

**文件**：`BusinessCanvasService.cs` 的 `ParseBlueprintMarkdown` 方法

**处理流程**：

```
LLM输出的Markdown文本
        ↓
按标题(#)分割章节
        ↓
提取超级签名（正则匹配"我是...用...帮..."）
        ↓
提取信任构建SOP（案例、资质、社交证明）
        ↓
生成结构化的BlueprintCard对象
```

**关键正则表达式**：

```csharp
// 提取"我是谁"
@"我是([^，,]+)"

// 提取"用...方法"
@"用([^，,，帮]+)"

// 提取"帮谁"
@"帮([^，,，解]+)"

// 提取JSON对象
@"\{[\s\S]*\}"
```

### 3.2 竞品分析解析

**文件**：`BusinessCanvasService.cs` 的 `TryParseCompetitiveAnalysis` 方法

**处理流程**：

```
LLM返回的文本
        ↓
提取JSON部分（可能有前缀/后缀文字）
        ↓
尝试完整JSON解析
        ↓
失败则部分解析（提取数组内容）
        ↓
仍失败则返回默认分析
```

### 3.3 阶段判定

**文件**：`DiagnosticEngine.cs` 的 `DetermineNextStage` 方法

**预设**：每个阶段的退出条件
**程序**：根据消息数量和当前阶段自动推进

│  • 进度计算规则                                              │
│  • 输出结构模板                                              │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    LLM 推理 (DeepSeek)                      │
│  • 理解用户输入                                              │
│  • 选择合适的追问层次                                         │
│  • 生成追问内容                                              │
│  • 计算进度百分比                                            │

└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                 程序后处理 (Post-Processing)                 │
│  • Markdown解析 → 结构化对象                                 │

                              │

│                    最终输出                                  │

│  • 生成可导出的PDF/Markdown文档                             │
└─────────────────────────────────────────────────────────────┘

## 六、总结

| 类型 | 内容 | 可修改性 |
|------|------|----------|
| **预设** | 5阶段流程、五层逼问模板、进度权重、输出结构 | 需改代码/JSON |
| **LLM生成** | 追问措辞、进度评估、蓝图内容、竞品洞察 | 取决于用户输入 |
| **程序处理** | Markdown解析、JSON提取、结构化存储 | 需改C#代码 |

**核心逻辑**：系统提供「骨架」，AI填充「血肉」，程序负责「整形」。
